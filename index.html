Movie Ticket Booking Platform

/projects/movie-ticket-booking

The problem

Seats are the one thing you can't sell twice. Two people can open the same show and pick the same seat within milliseconds, and if the app checks availability and saves the booking as separate steps, both requests can pass the check.

How I solved it

I lock the seat while a booking is being made, using pessimistic locking with JPA, so the second request waits and then finds the seat gone. Around that sits JWT login with user and admin roles, REST APIs for movies, theaters, shows, bookings and payments, city-wise show filtering and real-time seat availability.

    Real-Time Chat Application

    /projects/realtime-chat

    The problem

    A chat is only useful if everyone in the room sees a message the moment it's sent, without refreshing the page, and if people can tell who has come and gone.

    How I solved it

    A Spring Boot server speaks STOMP over WebSockets. People join a room and get its message history, everyone else sees a JOIN or LEAVE notice, and each message reaches the whole room instantly. The whole app runs in Docker with WebSocket support.

    1. BrowserSends a message
    2. STOMP over WebSocketOne open connection
    3. Spring BootRoutes it to the room
    4. Everyone in the roomSees it instantly
